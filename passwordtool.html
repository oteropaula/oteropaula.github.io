Overview

One tool, four functions

The application is a terminal-based tool with a numbered menu. The user moves through four sequential functions: generate a password that meets strict security requirements, check whether a stored password is compliant, encrypt a plain-text file using that password as the key, and decrypt the resulting file to recover the original. All intermediate results are saved to .txt files so that each step can be used independently. A 3-second cooldown is enforced between menu actions to prevent unintended rapid execution.

Module 1 - generador.py

Password generation

The requisitos() function prompts the user for four parameters: total length (12–128), number of symbols, number of digits, and number of uppercase letters. Validation logic catches negative values, out-of-range lengths, and combinations where typed characters exceed the total - all with descriptive error messages and automatic re-prompts from the beginning.

The automatico() function then fills the password slot by slot - symbols first, then digits, then uppercase letters, then lowercase to fill the remainder - before shuffling randomly using Python's random library so character types aren't grouped predictably. The final password is written to a .txt file named by the user. The generated password is also printed on screen immediately after generation.

Required

12–128 characters · at least 1 lowercase · at least 1 uppercase · at least 1 digit · at least 1 ASCII symbol · no spaces · no accented or regional letters (á, ñ, ç, œ…) · no 3+ consecutive characters from the username

Avoid

Dictionary words in any language · keyboard sequences (qwerty, 12345…) · personal information (name, birthdate, address, pets) · characters not present in the ASCII table (˜, ™…)

Tips for memorability

Uppercase at the start · digits at the end · same symbol at start and end · abbreviation of a memorable phrase with numbers intercalated · change every 6 months or at any suspicion of compromise

Customisable

Total character count · number of digits · number of symbols · number of uppercase letters · remaining slots auto-filled with lowercase · output filename chosen by user

Module 2 - comprobador.py

Password validation

The cumple_requisitos() function reads the password from a user-specified file and runs two independent checks. First it verifies that the password meets the user-defined parameters (the same counts entered during generation). Then it confirms the minimum security baseline: at least one character of each type - lowercase, uppercase, digit, symbol.

If either check fails, the output specifies exactly which requirement is unmet rather than a generic error. The return value is a boolean: True if fully compliant, False otherwise. The validation suite was tested with 18 parametrised pytest cases, all passing.

Modules 3 & 4 - encriptar.py · desencriptar.py

Character-level ASCII encryption

Encryption operates character by character using the generated password stored in clave.txt as the key. The algorithm is symmetric - the same key is required to decrypt. The core operation is applied to the ASCII ordinal value of each character.

Encryption - encriptar()

1.Read each character from the input .txt file.
2.Get its ASCII ordinal value with ord(char).
3.If ordinal is even → add 1: ord + 1
4.If ordinal is odd → subtract 1: ord − 1
5.Write the result to the output file in hexadecimal format (e.g. 0xa1 0xe3 0xc1…).

Decryption - desencriptar()

1.Read each hexadecimal value from the encrypted file.
2.Convert from hex to integer.
3.Apply the inverse: if value is even → subtract 1; if odd → add 1.
4.Convert back to character with chr().
5.Write the recovered character to a new .txt file - which must match the original exactly.

The password stored in clave.txt is required for both operations. Using a different key for decryption produces an unreadable output. Files are saved under new names (texto_cifrado.txt, texto_descifrado.txt) to preserve all versions. The encryption suite ran 4 parametrised pytest cases (all passed), and the decryption suite did the same independently.

Architecture

File structure & modules

final.py / programa_principal.py

Main program

Entry point. Presents the numbered menu, routes to each module, enforces the 3-second cooldown between actions, and handles the exit (option 5). Built by Julián and Oreto.

generador.py

requisitos() + automatico()

requisitos() collects and validates user parameters with descriptive re-prompts. automatico() builds and shuffles the password, then writes it to a named .txt file. Built by Julián and Alba.

comprobador.py

cumple_requisitos()

Reads the password file, runs user-defined and minimum-security checks, and returns True/False with a specific failure message. 18 pytest cases, all passed. Built by Julián and Alba.

encriptar.py

encriptar()

Reads the input file character by character, applies the ASCII even/odd ±1 transformation, and writes the result as space-separated hex values to the output file. Built by Oreto and Paula.

desencriptar.py

desencriptar()

Reads the hex-encoded encrypted file, checks the password matches, reverses the transformation, and writes the recovered plain text to a new file. Built by Oreto and Paula.

pytest suites

Acceptance tests

Generation: 4 parametrised cases (min/max/intermediate length, varied character counts). Validation: 18 cases covering True/False edge cases. Encryption + decryption: 4 cases each. All suites passed at 100%.

Reflection

First-year project, lasting lessons

This was one of the first substantial Python projects in the degree and my introduction to thinking about security from a technical standpoint. Looking back, the most valuable part wasn't the encryption algorithm itself - which is intentionally simple - but the discipline of writing modular, testable code from the start. Separating generation, validation, encryption and decryption into distinct files, each with clear responsibilities, made the pytest suites straightforward to write and the bugs much easier to isolate.

The security research component - password length tables, brute-force attack timelines, ASCII character compatibility across keyboard layouts - was an early introduction to the human factors side of security: the gap between what a system enforces and what users actually do. That thread has stayed with me through later coursework in cybersecurity and social engineering.
